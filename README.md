> 在浏览器里读 PDF，随手划线、写批注，一键导出成能直接丢给 AI 的标注包。

**简体中文** | [English](./README.en.md) | **在线试用 → https://aigeekops.github.io/PDFMark/**

![界面总览：左侧目录，中间原文与高亮，右侧批注面板](docs/screenshots/overview.png)

读论文、合同、研报的时候，划线和批注都锁在阅读器里；想拿给 AI 做总结，还得翻回去一条条复制。
PDFMark 把这条链路收成一条：**读 → 划 → 批 → 导出 → 摘要**，文件全程不离开你的电脑。

- 纯前端，零后端，`npm run dev` 就能跑；构建产物是静态文件，丢哪都能托管
- PDF、标注、以及「读到第几页」都存在浏览器 IndexedDB 里，按文件内容指纹识别，重开浏览器接着上次读
- 导出两份东西：给人看的《划线与批注》，和给 AI 看的《阅读标注包》
- 也可以填自己的模型地址，在应用里直接出摘要

## 功能

**读**

| 能力 | 说明 |
| --- | --- |
| PDF 渲染 | pdf.js，逐页 canvas 绘制，滚动到哪画到哪 |
| 目录导航 | 读 PDF 内置书签，树形展开，点击跳页，滚动时自动高亮当前章节；没有书签也能按页码跳 |
| 文字复制 | 切到「选文字」模式，像网页一样拖选，`Ctrl / Cmd + C` 拿走 |
| 全文搜索 | `Ctrl / Cmd + F`，跨页搜索，命中在原文上标黄，结果列表点了就跳 |
| 阅读进度 | 自动记住每份文档读到哪一页，重开直接落回原处；启动时优先打开你最近读的那份 |
| 缩放 | 50% – 300%，标注跟着文字走，不跑位 |

**划**

| 能力 | 说明 |
| --- | --- |
| 四种标注 | 高亮 / 下划线 / 删除线 / 区域框，各 5 种颜色 |
| 贴合文字 | 高亮贴着字形走，不是一个大方块 |
| 原文回填 | 划完自动把命中的文字提出来存好，导出时不用回头翻 |
| 批注 | 每条标注都能写一段批注，支持搜索、按颜色与类型筛选、只看有批注的条目 |
| 一键复制 | 标注卡片上点「复制」拿走原文（带批注） |

**导**

| 能力 | 说明 |
| --- | --- |
| 笔记 Markdown | 按页分组的划线与批注清单，给人看；模板可改 |
| AI 标注包 | 文档信息 + 划线引用 + 批注 +（可选）原文，配套提示词单独给出，范围可调；模板可改 |
| 分片导出 | 长文档按页切成几片，每片只带本片的标注和原文，逐片喂给模型再合并 |
| 带标注的 PDF | 把标注写成标准 PDF 批注导出副本，Acrobat / Preview / Chrome 都能看到和编辑 |
| 内置摘要 | 填自己的 API 地址 / Key / 模型，流式出摘要；设置里可「测试连接」，填完立刻知道通不通 |
| 备份 / 导入 | 标注导成 JSON，换设备再导回来 |

## 快速开始

不想装环境就直接开 **https://aigeekops.github.io/PDFMark/** —— 和你本地跑的是同一份构建，
静态托管，数据一样只留在浏览器里。

```bash
npm install
npm run dev        # 开发模式，默认 http://localhost:5173
npm run build      # 类型检查 + 构建，产物在 dist/
npm run preview    # 本地预览构建产物
npm run typecheck  # 只做类型检查
```

需要 Node.js 18 或更高版本。

`dist/` 是纯静态目录，GitHub Pages / Vercel / Netlify / 对象存储都能直接托管。
`vite.config.ts` 里的 `base` 已设为相对路径，放在子目录（比如 `user.github.io/pdfmark/`）也能正常加载资源。

本仓库已经带了一份 Pages 部署流程（`.github/workflows/deploy.yml`）：推 main 就 `npm ci` → `npm run build`
→ 发布 `dist/`。**注意 Pages 的 Source 必须设成 "GitHub Actions"**，不能用默认的「分支根目录」——
后者会把仓库根当成网站，而根目录的 `index.html` 是开发用的入口（`/src/main.tsx`），
浏览器执行不了 TypeScript，打开就是一片空白。

## 完整链路

1. **打开** — 把 PDF 拖进窗口，或点「打开」。文件自带书签的话，左侧目录会自动展开。
2. **划** — 顶部选工具和颜色，按住拖一段就划上了。双击可以只选中一个词。
3. **批** — 右侧「批注」面板给每条划线写注释。点条目跳回原文位置。
4. **导** — 右上「导出」，选「AI 标注包」，整段复制。

几百页的长文档导出时勾上分片，避免一次塞爆上下文。

![导出 AI 标注包：可选原文范围，实时估算 token 数](docs/screenshots/export-ai-package.png)

导出范围有三档，按材料多少和模型上下文挑：

- **只给划线片段** — 最省 token，适合模型已经知道全文的情况
- **划线 + 所在页全文** — 默认，给足上下文又不会太长
- **划线 + 全文** — 材料不长、或者想让模型做全局判断时用

对话框里会实时估算 token 数，不用猜。

**分片**：选「每片 N 页」后，标注包按页范围切成几片，每片只带本片页范围内的标注和原文，
片头写明「本片是第 k 片（共 a–b 页）」。逐片粘给模型，最后自己把几份摘要合起来。

**带标注的 PDF**：导出一份新文件，标注变成标准 PDF 批注 —— 高亮 / 下划线 / 删除线写成文字标记
批注（带 `QuadPoints`，贴着字形），区域框写成方形批注，批注文字写进批注内容字段。
原文永远不动，导出的始终是副本。

## 导出格式

### AI 标注包

标注包本体是纯 Markdown。对话框会**另外**给出一段配套的指令模板并附带复制按钮 —— 你可以
只拿走标注包，自己写提示词；也可以连模板一起复制。真实输出长这样：

````markdown
# 阅读标注包：《some-paper.pdf》

| 项目 | 值 |
| --- | --- |
| 文件 | some-paper.pdf |
| 页数 | 2 |
| 标注数 | 3（带批注 2 条） |
| 导出时间 | 2026-10-10 01:45 |
| 原文范围 | 划线所在页全文 |

## 一、我的标注与批注

### 第 1 页

> The quick brown fox jumps over the lazy dog.

- 我的批注：这一句是全文的定调，后面都在论证它。

> Highlight this sentence and leave a note about it.

- 我的批注：和第 5 行的 context window 是同一个论点。

> Context windows are finite, so annotations matter.

- （下划线，无批注）

## 二、附：相关页原文

### 第 1 页

Chapter One - Getting Started
...
````

配套的指令模板（对话框里单独给出，带复制按钮）：

```text
你是一位严谨的阅读助理。下面是一份 PDF 的阅读标注包，包含：读者划线的原文片段、
读者自己写的批注，以及（可选）相关页的全文。
请严格基于这些内容作答：
1. 先用 5-8 条要点概括重点，每条一句话，附「第 N 页」出处；
2. 单独列出「读者重点关注」：从批注里提炼读者的主张、疑问和待办；
3. 给出 3 个值得进一步追问的问题；
4. 如果材料不足以支撑某个结论，明确说「材料未涉及」，不要编造。
输出中文，Markdown 格式，不要复述我的指令。
```

### 笔记 Markdown

给人看的一份，按页分组：

```markdown
# 《some-paper.pdf》划线与批注

- 标注 3 条，其中带批注 2 条
- 导出时间：2026-10-10 01:46
- 工具：PDFMark

## 第 1 页

> The quick brown fox jumps over the lazy dog.

**批注：** 这一句是全文的定调，后面都在论证它。
```

两份都可以「复制」或「下载」。

## 配置模型（可选）

点右上「设置」，填三样：

- **API 地址** — 任何兼容 `POST /chat/completions` 的网关，例如 `https://api.openai.com/v1`、`https://api.deepseek.com/v1`、`https://open.bigmodel.cn/api/paas/v4`。
  填到版本号就行；把服务商文档里那种完整端点（`…/v1/chat/completions`）整段粘进来也能用，应用不会再拼第二遍。
- **API Key**
- **模型名** — 填服务商给的准确 ID，比如 OpenRouter 的免费档是 `nvidia/nemotron-3.5-lightning:free`

设置里有几个常见服务商的快捷填充（OpenAI / OpenRouter / DeepSeek / Moonshot / 智谱 / 硅基流动），填完点一下省得手打。

**填完先点「测试连接」。** 它会发一句话给模型并把结果直接显示在下面 —— 通了会告诉你耗时和模型的回话，
不通会告诉你卡在哪一步（地址拼错、网络不通、CORS 被拒、Key 无效、模型名不存在……）。
比划完一段标注再点「生成摘要」、然后盯着一个动也不动的按钮效率高得多。

> Key 只存在本机浏览器的 `localStorage`，代码里没有任何硬编码密钥，仓库里也不会有。
> 换浏览器、换设备、清了站点数据都需要重新填。

请求有两个超时兜底：发出去 30 秒没有任何回应就判定失败并报错，连上之后 60 秒没有新内容也会停。
等待期间界面上会显示已等了多少秒。所以不会出现「按钮一直显示停止、页面没反应」这种情况 ——
那种状态以前是真的会发生，因为浏览器不会替你把一个挂住的请求判死。

不配也能用 —— 导出里的标注包手动粘给任何 AI 对话窗口即可。

## 和同类工具的关系

PDF 标注是个被做透的领域，这个项目不假装是唯一解。选之前先看看你属于哪种情况：

| 你的情况 | 通常更合适的 |
| --- | --- |
| 管理成百上千篇文献，要引用格式、要挂附件 | Zotero（配合 Better Notes 插件导出 Markdown） |
| 本来就在 Obsidian 里写笔记，想让标注进 vault | Obsidian + PDF Annotator 一类插件 |
| 主要读 EPUB，顺手读点 PDF，要跨设备同步 | Koodo Reader |
| 需要多人对着同一份文档讨论 | Hypothesis |
| 只是偶尔标一下、签个名 | Firefox / Chrome 自带的 PDF 阅读器 |
| 想把整本书丢给 AI 直接问答，不需要精读划线 | NotebookLM（已改名 Gemini Notebook） |

PDFMark 挑的是另一个位置：

- **不装软件** — 一个网页，浏览器打开就能用，手机上也能划
- **不上传** — 没有账号、没有服务端，PDF 不进任何人的数据库
- **导出面向模型，不只是面向自己** — 多数工具的导出是「给你日后翻笔记用的」；这里默认产出的是「给模型读的」，所以它带原文范围选项、token 估算和现成的提问模板

代价也说清楚：没有文献管理，没有跨设备同步，也没有协作。这三条都做的话，就该去用上面那些工具了。

## 数据与隐私

- PDF 文件、标注、以及「读到第几页」的进度全部存在浏览器本地 IndexedDB（库名 `pdfmark`）。
- 唯一会发生的网络请求是**生成摘要** —— 请求打向你**自己配置**的模型地址，内容是标注包。
- 没有账号、没有埋点、没有遥测、没有第三方统计脚本。
- 清掉数据：浏览器设置里清除本站点数据即可；标注可以先导出 JSON 备份。

## 实现细节

几个不太显然的地方，改代码之前值得先看一眼。

**标注存的是页面坐标，不是屏幕像素。** 每条标注记录的是 PDF 用户空间（单位点，原点左上）
下的矩形，缩放、换设备、重新渲染都不会让标注跑位。屏幕坐标只在交互的瞬间用来换算。

**高亮贴着字形。** 拖选一段时，先算出框住了哪些文本 run，再按 run 的实际字形尺寸生成矩形，
同一基线上的连续 run 自动合并成一条。所以高亮是贴合文字的带子，而不是一个覆盖整行的大方块。
划线命中的原文也在这一步一并提取出来存进标注，导出时直接用。

**划线模式和选文字模式互斥。** 两者都要抢同一批鼠标事件：`annotate` 模式下 SVG 蒙层接管拖拽；
`select` 模式下换成一层透明的文字 DOM 接管，交给浏览器原生选区。所以顶栏做成两个互斥按钮。

**文字层没有用 pdf.js 的 textLayer。** 而是拿已经提取好的 run 自己摆了一层透明文字。
原因是 PDF 里的字形宽度和浏览器字体的渲染宽度对不上：`getBoundingClientRect()` 量出来的比
PDF 真实宽度要宽，直接摆会让选区蓝底随着行变长逐渐偏离底下的文字。所以每个 span 渲染后都会
再量一次自然宽度，用 `scaleX` 压回 PDF 里的真实宽度。

**目录解析要处理两种书签目标。** 命名目标（字符串）需要先 `getDestination()` 查一次；显式数组
的首元素可能是页引用对象，也可能是字面页码，都要兼容。解析不出目标的书签仍然显示出来，不丢。

**页面的文字只有一个来源。** `resolvePageText()` 依次查内存缓存、PDF 内嵌文本层。
搜索、导出、划线命中都走这个函数，所以文本提取只有一条路径，不散落各处。

**写回 PDF 要做一次坐标翻转。** PDFMark 存的是页面坐标（原点左上，y 向下），PDF 批注字典要的是
用户空间（原点左下，y 向上）。每个 y 都要经 `pageHeight - y` 翻一次；`QuadPoints` 每个四边形
四个角按「左上、右上、左下、右下」排列。写的是副本，IndexedDB 里的原文从不被改动。

**搜索的匹配是宽容的。** 查询里的空白匹配「零个或多个字符」，因为 PDF 文本在任意位置被切成 run，
`the quick` 有可能落在一个不带空格的 run 边界上。命中区间通过一个「字符 → run 下标」的对照表
回推成矩形，所以在页面上能直接标黄。

**阅读进度单独存一条记录，不挂在文档上。** 挂在文档记录里最省事，但那样每翻一页都要把整个 PDF
二进制重写一遍。所以它是独立的一张表（`progress`，键是文档指纹），当前页稳定 700 毫秒后才写一次。
恢复时也有两个坑：页面几何是异步到的，按第一帧量到的高度滚会偏出去，所以要连着几帧重新对齐；
落位前还有一段静默期，否则把恢复过程中的第一帧当成进度存回去，下次打开就变成第 1 页了。

**当前页取的是「视口顶部所在的那一页」，不是最靠上的可见页。** 观察器带 800px 的预加载边距，
上方看不见的页也在回调里，直接取最靠上的那个会让进度和目录高亮整体偏前一页。

## 已知限制

- 竖排或旋转文本的框选位置是近似的。
- 没有文字层的扫描件（整页是图片的 PDF）划不出引用文字，只能画区域框。
- 标注粒度是「矩形 + 引用文本」，不是字符级的精确选择。
- 写回 PDF 目前是**追加**批注，不会读进原文件里已有的批注，也不会合并它们。
  没有生成 `AP`（外观流），绝大多数阅读器会用默认外观渲染，少数老阅读器可能只显示批注图标。
- 几百页的大文件首次打开要逐页提取文本，慢一些；已做可见性懒渲染和文本缓存。
- 标注存在浏览器本地，清站点数据会丢；换设备要靠 JSON 备份手动搬。

## 路线图

第一版列的事都做完了：

- [x] 标注写回 PDF 文件，让 Acrobat / Preview 也能看到
- [x] 页内搜索
- [x] 标注列表按颜色 / 类型筛选
- [x] 标注导出的模板可自定义
- [x] 长文档的分片导出

接下来的方向，按优先级排，欢迎认领：

- [ ] 给写回的批注生成外观流（`AP`），让不自动渲染的阅读器也能正确显示
- [ ] 读进原 PDF 已有的批注，和自己的标注一起显示
- [ ] 搜索支持全词匹配 / 大小写敏感开关
- [ ] 整页文本一键复制（读长文喂 AI 时省事）
